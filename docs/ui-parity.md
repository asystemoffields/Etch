# UI parity with Microsoft Word

How Etch looks and feels next to Word: ribbon, dialogs, panes, keyboard, mouse and touch.
Typing behaviour has its own checklist ([`typing-parity.md`](typing-parity.md)). All assets are our
own (`AGENTS.md`: no Microsoft iconography, ever).

Document title opens Rename Document; the account badge opens Options › General for user name and initials. Saved documents retain their format and refuse conflicting names; desktop renaming requires a filesystem that supports hard links. Web renaming changes the next download name. An unsaved document's name is only the name Save suggests: its Title property is left alone.

## Native save conflicts

A user-initiated native Save that detects an external change opens a short dialog: Keep editing
retains the unsaved document; Save Copy opens the existing asynchronous picker with a distinct
suggested name. A cancelled picker writes nothing; its answer is bound to the document that
opened it. Picking an alias of the conflicting file is refused again. Save before Close/New/Open
also retains edits on conflict. AutoSave pauses and reports the conflict once. Programmatic
engine calls return the typed error without opening a dialog. The dialog uses theme tokens and
translation lookups; new text may fall back to English pending native-language review.

Save Changes exposes the document-specific question as an alert-dialog name and the loss warning plus any failed-save explanation as its description. Full-app AccessKit coverage checks the focused choice's dialog ancestry, all three choices and cancellation. This is accessibility-tree evidence; native Windows screen-reader and spoken VoiceOver verification remain pending. Visual layout, wording and save policy are unchanged.

The Language dialog reads effective character formatting, including document defaults, paragraph styles and character styles. Accepting it unchanged keeps inherited language and no-proof choices; explicit direct formatting still takes precedence. Other proofing and Windows-specific reports remain separate.

## Find navigation

Find selects the Results tab, including when it prefills selected text. Editing the search query also reveals matching or empty results. Manual Headings and Pages navigation remains available until the next search action.

Footnote and endnote editing keeps body and note text at normal opacity, on light and dark pages. Headers and footers still dim outside their editing context.
